# 工单接口调用说明

新建工单的 `id` 与 `ticket_id` 使用 `ITYYYYMMDDNNNN`，例如 `IT202611110001`。日期按北京时间取建单日期，四位流水在同一数据库内跨处理组递增，每日从0001开始。已有UUID工单继续使用原编号，查询、动作及旧单关联均兼容。调用方应保存接口实际返回的完整字符串。单日达到9999后新建返回409，错误码 `ticket_number_exhausted`。同会话重试仍返回原单。

更新于2026-11-11，供后端与工单AI负责人进行本地接口联调。对应接口表中的当前实现列。服务地址以实际启动端口为准，交互文档位于同服务的 `/docs`。

## 身份与查询范围

现有接口使用员工登录得到的 `Authorization: Bearer <access_token>`。`POST /api/v1/auth/login` 接收 `username` 和可选 `password`，返回 `access_token`、`token_type`、`expires_in`。本地测试工号免密取决于 `IT_ADMIN_IAM_PASSWORDLESS=1`。正式机器人服务凭证与可信员工身份绑定待接入。

员工“我的工单”使用 `GET /api/v1/tickets?scope=mine`，详情使用 `GET /api/v1/tickets/{ticket_id}?scope=mine`。`mine` 要求提交人角色，并严格按当前登录账号的 `submitter_id` 查询，即使该员工同时有分派或处理角色也只返回本人提交的工单。工号通过IAM关联登录账号，当前业务接口的本人判断取登录身份。

`scope` 支持 `visible` 和 `mine`，默认 `visible`，按角色权限并集查询。详情不可见或不存在统一返回404。机器人接入时须将可信员工身份与业务调用绑定，采用本人范围。待处理状态集合仍待双方确认。

## 建单与附件

先创建会话，再在员工确认后创建工单。保存会话编号用于恢复及重试。

```http
POST /api/v1/conversations
Authorization: Bearer <access_token>
Content-Type: application/json

{}
```

响应201中的 `id` 为会话UUID。`GET /api/v1/conversations/{conversation_id}` 可查询当前会话的 `ticket_id`。

通过 `POST /api/v1/attachments` 上传附件，采用 `multipart/form-data`，每个文件重复使用 `files` 字段。每次1～5个非空文件，单文件最多10 MiB，请求体最多50 MiB加64 KiB协议开销。成功201返回 `items`，每项包含 `file_id`、`file_name`、`size`、`content_type`、`created_at`。整批校验和保存失败会回滚。上传声明的媒体类型作为元数据保存，下载统一二进制。

```http
POST /api/v1/conversations/{conversation_id}/ticket
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "service_system_id": "test-office",
  "title": "打印机无法连接",
  "description": "员工确认的故障说明",
  "priority": "P3",
  "file_ids": ["<上传返回的文件UUID>"]
}
```

无附件时可省略 `file_ids` 或传空数组。部门、邮箱、地点由登录账号的IAM资料带入并保存建单快照。可选 `location` 去空白后最多200字符，空值沿用账号地点。运维系统ID通过 `GET /api/v1/service-systems` 获取。正式系统分类待适配。

可选 `priority` 接收 `P1`、`P3` 或 null，省略及null保存为空。历史工单迁移后优先级为空。建单、列表、详情和动作响应均返回 `priority`。页面可手动选择，当前仅保存及展示所选值。优先级判定和处理规则暂缓。

建单首次201，同会话重试200返回原工单及当前附件。重试请求中新填的正文或 `file_ids` 不会修改原单。建单、绑定和初始历史同事务提交。

原工单追加附件使用下列请求，先读取详情获取最新 `version`。

```http
POST /api/v1/tickets/{ticket_id}/attachments
Authorization: Bearer <access_token>
Content-Type: application/json

{"expected_version": 1, "file_ids": ["<上传返回的文件UUID>"]}
```

当前提单人可以在待分派、待接单、处理中、待员工确认阶段追加。成功200返回更新工单及 `files`，新增附件增加版本和历史。相同文件在同一工单重复绑定不重复新增，旧版本仍返回409。

详情的 `files` 提供已绑定附件元数据。通过带员工Bearer的 `GET /api/v1/attachments/{file_id}` 下载。未绑定文件仅上传者可下载，已绑定文件按工单可见权限校验。文件不可访问或不存在统一404。

## 员工补充说明

当前提单人可在待分派、待接单、处理中、待员工确认阶段向原工单追加文字及附件。

```http
POST /api/v1/tickets/{ticket_id}/supplements
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "expected_version": 1,
  "description": "员工追加的现场现象",
  "file_ids": ["<上传返回的文件UUID>"]
}
```

`description` 可省略或为null，去首尾空白后最多10000字符。`file_ids` 默认空数组，最多5项，复用现有上传及归属规则。文字与附件至少一项非空，否则422。原始工单描述保留，补充文字写入 `history` 中的 `supplement_added` 记录，`note` 保存文字，`actor_id` 和 `created_at` 保存人员及时间。

成功200返回更新工单及 `files`。文字、文件绑定、版本及历史在同一事务内提交。发生实际补充时版本增加一次，工单状态保持当前值。仅提交已绑定同单的附件且无文字时返回当前工单。旧版本返回409，响应丢失后先读取详情的历史、附件及版本核对。文字相同且使用新版本再次提交会形成新的补充记录。

## 列表、搜索与响应字段

```http
GET /api/v1/tickets?scope=mine&q=PLM&limit=20&offset=0
Authorization: Bearer <access_token>
```

支持可选 `status` 单状态、`service_system_id`、`q`。`q` 最多200字符，去首尾空白后匹配标题、描述、运维系统名称的子串，或完整工单编号。SQLite `lower` 提供ASCII字母大小写不敏感匹配，特殊符号按字面处理。所有条件与权限条件同时生效。`limit` 默认20、最大100，`offset` 默认0。`items` 与 `total` 在同一读事务内按同一组条件查询。

建单、列表项、详情及工单动作响应新增以下字段。

| 字段 | 含义 |
| --- | --- |
| ticket_id | 等于 `id` 的工单编号，可直接保存并用于后续调用 |
| system | `service_system_id` 对应的当前运维系统名称 |
| engineer_employee_no | 当前处理人已关联IAM的工号字符串，未分派或无映射时为null，保留前导零 |
| created_at_iso | 创建时间的ISO8601格式，采用北京时间 `+08:00` |
| updated_at_iso | 更新时间的ISO8601格式，采用北京时间 `+08:00` |

原有 `id`、`service_system_id`、`assignee_id` 及整数 `created_at`、`updated_at` 继续可用。名称和工程师工号按当前字典及IAM映射读取，人员部门、邮箱、地点使用建单时快照。

当前状态为 `pending_assignment` 待分派、`pending_acceptance` 待接单、`in_progress` 处理中、`awaiting_confirmation` 待员工确认、`closed` 已关闭、`cancelled` 已撤销。接口表中的待补全、独立已解决状态及中文状态适配待双方定稿。

## 处理结果确认与备注

读取详情中的 `version`、`result_round` 和处理结果，员工明确确认后调用。

```http
POST /api/v1/tickets/{ticket_id}/confirmations
Authorization: Bearer <access_token>
Content-Type: application/json

{
  "expected_version": 4,
  "result_round": 1,
  "outcome": "resolved",
  "note": "员工确认已经恢复"
}
```

仅当前提单人可在 `awaiting_confirmation` 确认。`resolved` 关闭为 `closed`，`unresolved` 回到 `in_progress`。成功200返回更新工单。`note` 可省略或为null，去首尾空白后最多10000字符，空白按无备注处理。备注随本次确认动作写入历史，与状态、结果确认及版本更新同事务提交。

## 错误与恢复

业务错误采用 `{"detail":{"code":"...","message":"..."}}`。字段校验422返回 `detail.code=invalid_request`、`detail.message` 和 `detail.fields` 数组，错误项含字段位置及说明，响应过滤原始输入值。

| HTTP状态 | 调用方处理 |
| --- | --- |
| 401 | 登录会话无效或过期，重新取得对应员工会话 |
| 403 | 角色或动作权限不足，停止该动作并提示 |
| 404 | 记录不存在或当前身份不可访问，按不可访问处理 |
| 409 | 版本、轮次或状态冲突，重新读取详情并让员工核对后再提交 |
| 413 | 附件数量或大小超过接收限制，缩减本次上传 |
| 422 | 字段、运维系统、文件归属等校验失败，根据错误更正 |
| 503 | 数据库暂不可用或IAM连接失败等，保留上下文并提示稍后处理 |

超时后先恢复查询。建单复用已保存的会话UUID，查询会话是否已有 `ticket_id`，必要时重试同一会话建单。附件追加或确认响应丢失后，先读取详情的版本、附件及历史核对，再决定下一步。重复上传会生成新的文件UUID，来源上传去重和未绑定文件清理待约定。
