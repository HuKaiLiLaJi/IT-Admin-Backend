# 内部 IT 行政工单后端业务范围与决策说明

面向：项目后端负责人。业务整理日期：2026-11-04；新目录适配日期：2026-11-05。

本文帮助你明确工作范围、识别原 PRD 的问题，并与机器人、前端和业务负责人划清责任。建议将你的职责定位为“问题记录与人工工单的业务后端负责人”。你已表示预计负责后端、机器人不再归你负责；具体团队分工尚未最终确认。

文中的建议供评审，不因整理成文档就成为已批准需求或开发授权。执行细节见 [后端业务执行交接](后端业务执行交接.md)。

## 业务主线与已确认规则

员工提问 → 记录问题 → 机器人尝试回答 → 按条件转人工 → 分派接单 → 人工处理 → 员工确认结果 → 关闭，并可自愿评价。

根据 [需求说明](requirements.md) 和决策 D10～D14，以下原则已经确认：

- 所有问题都记录，包括机器人直接解决的问题。
- 员工表示未解决、主动要求人工、机器人无法回答、问题需要人员实际操作，任一条件成立时转人工。
- 处理人提交结果后，员工确认是否解决；未解决则继续处理。
- 满意度和是否解决分别记录。人工评价自愿，确认解决后未评价也可以结单。
- 机器人回答不要求评价；机器人直接回答后的解决结果如何确认仍待细化。

建议区分“问题记录”和“人工工单”：前者记录咨询与反馈，后者承载需要人工跟进的事项。这样既不遗漏咨询，也不把所有咨询都算作人工工作量。该对象划分尚待确认。

## 你的职责与协作边界

| 板块 | 你的后端职责 | 其他角色职责 |
| --- | --- | --- |
| 问题记录与受理 | 保存问题及必要反馈，接收人工请求，返回工单编号 | 机器人收集信息、追问并识别转人工原因 |
| 分派与处理 | 分类、处理组、负责人、接单、改派、进展及历史 | IT／行政确定人员分工并实际处理问题 |
| 结果与评价 | 验证并保存员工确认，执行状态流转，保存评价 | 机器人或前端展示入口并传递员工实际选择 |
| 权限与查询 | 控制谁能查看和修改哪些内容 | 接入方提供可信身份，人员映射归属共同确定 |
| 通知 | 确定通知时机、对象和内容，跟踪任务结果 | 企微接入方负责发送、重试和结果回传 |
| 工作台与报表 | 提供列表、详情、配置及统计接口 | 前端开发页面，业务方确定统计口径 |
| 智能问答与知识 | 后续需要时提供获授权的数据接口 | AI 负责人负责模型、检索和回答，业务人员审核知识 |
| 运维 | 提供服务运行要求并配合排错 | 部署、监控和备份需另行明确负责人 |

建议工单状态统一由后端管理。机器人可发起业务请求，后端验证权限、检查规则并保存结果；机器人、卡片和后台展示后端返回的状态。是否使用独立网页或企微卡片仍待确定。

可以向团队这样介绍你的职责：

> 我负责问题记录与人工工单业务后端，包括受理、分派、处理流转、结果确认、评价、权限及统计接口。机器人负责企微对话、知识问答、信息收集与交互展示，前端负责工作台和管理界面。身份来源、通知发送和接口交接由相关负责人共同确定，工单状态由后端统一管理。

其中评价自愿、员工确认结果已经确定；其他具体改法多数仍是建议，不能直接当作产品验收要求。

## 建议优先拍板的事项

前四项直接影响核心设计。参与角色不代表实际人员已分配。

| 顺序 | 要决定什么 | 建议起点 | 参与确认 |
| --- | --- | --- | --- |
| 1 | 受理对象和最低建单条件 | 问题与工单分开，分类不明可以人工分诊 | 你、业务方、机器人负责人 |
| 2 | 状态与无人回复处理 | 待分派 → 待接单 → 处理中 → 待员工确认 → 已关闭；无人回复不直接视为解决 | 你、业务方 |
| 3 | 无人承接和改派责任 | 明确兜底负责人，改派保留原因和历史 | 业务方、你 |
| 4 | 身份和权限 | 员工看本人，处理人按分配范围，管理员范围明确；身份由可信接入提供 | 你、身份接入方、业务方 |
| 5 | 第一版交付范围 | 先完成人工处理闭环，自动轮询和复杂 SLA 后续评审 | 你、业务方、项目负责人 |
| 6 | 通知和页面交付 | 后端产生通知任务，接入方发送，前端交付工作台 | 你、企微接入方、前端 |
| 7 | 时限及统计口径 | 明确业务时间后统一 SLA、首响和解决时长 | 业务方、你 |
| 8 | 工单以外的范围 | 软件分类不等于系统集成，采购审批和资产管理单独评审 | 项目负责人、业务方 |

建议把分类与地点分开，例如“IT／网络，杭州，杭州 IT 支持组”，避免每增加一个地点就增加一套分类。

## 第一版交付建议

第一版后端应能演示：接收人工请求、建单、分派接单、记录处理、提交结果、员工确认、关闭或继续处理、自愿评价。配套提供必要权限、处理历史、通知对接和基础查询统计。

自动轮询、复杂 SLA、多人协作、相似工单合并和高级报表可以后续评审。基础版本仍需明确谁兜底、谁通知、谁有权操作。模块划分不意味着需要拆成多个服务。

机器人问答仍是整个产品的流程，由其他负责人交付。你可以用模拟输入开发已获授权的后端范围，但完整业务验收需要机器人、接入方和前端共同参与。
