# 分对话实施计划

## 使用规则

工作目录为 D:/IT-Admin-Backend。项目约束以 [AGENTS.md](../AGENTS.md) 为准，业务规则以 [requirements.md](requirements.md) 和 [decisions.md](decisions.md) 中已确认条目为准。架构文档中的早期待决标记按后续决定理解。环境信息见 [development.md](development.md)。

六个任务在同一工作目录按 T01 至 T06 顺序执行。用户后续指定 T01 在当前对话实施，T02 至 T06 分别使用新对话。前一个任务完成并更新交接后，再启动下一个任务。每个任务都通过真实入口完成本阶段最小可用功能及风险相关验证，权限和事务随功能落实。

本文件记录拆分方案。用户发出对应任务指令后，实施授权按该任务范围执行。动态进度见 quick-resume.md。

## 通用执行与交接要求

- 接手先读 quick-resume.md，再按本任务需要读取需求、决策、开发状态和相关源码。核实前置任务的实际文件与验证记录。
- 复用已有 .venv 和前置实现。共享数据结构、错误格式、权限逻辑和事务边界优先沿用已有约定，必要变更兼顾既有调用。
- 每阶段补齐当前接口需要的权限检查、字段校验、事务及操作历史，避免向后续任务转交可被越权调用的接口。
- 工程选择保持最小可用，并记录具体选择及理由。依赖尚未明确的业务规则时，列明问题，只暂停受影响部分。
- 只做本任务及必要的前置缺陷修复。按项目规则进行针对性验证，记录执行命令、结果、未验证范围与遗留问题。
- 完成后在 development.md 增量记录启动方式、接口、数据结构约定和验证证据，在 quick-resume.md 更新实际状态、当前授权、接续点及下一任务。本计划保持稳定，动态进度集中在 quick-resume.md。
- 本阶段存在未完成项时如实交接，后续先处理所依赖的缺口。达到本阶段验收后结束本对话。

## T01 应用基础、数据库与本地测试身份

**前置** 环境准备已完成。

**范围** 建立最小 FastAPI 应用及稳定启动入口，接入本地 SQLite，确定数据库初始化与连接生命周期。实现可用的本地测试身份、角色与处理组范围，以及测试分类。提供后续接口复用的当前身份和权限检查入口，覆盖提交人、分派人员、处理人、主管等已确认测试角色。

**验收** 服务可以启动并进行健康检查，测试身份可建立和结束会话，未认证请求被拒绝，客户端自行填写用户编号或角色不能取得他人权限。数据库初始化可重复执行，重启后所需配置可读取。测试数据初始化与正常启动分开，重复运行不清空已有数据。说明测试账号的使用方式与本地运行限制。

**交接** 应用启动命令、数据文件位置及初始化方式、身份与角色范围表示、受保护接口接入方式。后续任务新增业务表时延续兼容的初始化策略。

## T02 会话、建单与权限查询

**前置** T01 完成。

**范围** 后端创建会话编号，建单必填字段及测试分类校验，一会话最多一工单，重复提单返回原单。关闭或撤销后再次报障使用新会话与新工单，并保留旧单关联。实现工单列表、详情、初始历史及按角色和范围过滤的查询。问题记录模块保留关联扩展位置。

**验收** 提交人来自可信登录上下文，必填字段缺失无法建单。同一会话重复与并发提交只形成一单，失败不留下部分业务状态。员工只看到本人工单，其他测试角色按既定范围访问，列表总数和详情均受权限限制。旧单关联规则若依赖 T04 的终态入口，当前验证可通过明确标识的测试夹具完成，并在 T06 补充真实入口验证。

**交接** 会话与工单接口、数据关系、去重约束、查询过滤及历史记录约定。

## T03 分派、接单、改派与处理记录

**前置** T02 完成。

**范围** 手工分派测试处理人，待分派到待接单再到处理中的状态转换，改派及公开处理备注。为动作保存操作者、关键时间和历史，采用最小充分的并发保护。

**验收** 非法状态、越权动作及无效处理人被拒绝。改派后原处理人失去查看权限，提交人可查看分派、改派和处理记录。并发接单或改派冲突有可处理的失败结果，业务状态与历史保持一致。改派允许的状态及目标状态如缺少已确认规则，只暂停相应分支并提出具体待决项。

**交接** 状态动作接口、并发冲突约定、当前负责人权限和处理记录格式。

## T04 处理结果、员工确认与撤销

**前置** T03 完成。

**范围** 处理人提交结果进入待员工确认，员工确认未解决回到处理中，确认已解决关闭，未回复保持待确认。实现前期直接撤销及处理中以后撤销申请、授权处理，保留原因和历史。

**验收** 只有对应提交人可确认，旧轮次或重复请求不会破坏当前处理状态。关闭时间与确认结果一致，关闭不依赖评价。直接撤销受状态和提交人约束，撤销申请与最终撤销分别留痕。撤销授权人员的具体角色或范围在现有资料无法确定时，先完成其余流程，再针对该权限提出确认。

**交接** 各终态及时间字段、结果轮次、撤销申请处理契约，为 T05 提供可靠的关闭时间来源。

## T05 评价与基础评价统计

**前置** T04 完成。

**范围** 好评、中评、差评，确认解决并关闭后七个自然日内评价及修改，到期锁定，中差评必填原因。无评价到期自动好评，已有评价保持原结果，分别记录主动与自动来源，并提供已授权范围内的基础统计和实际参与率。

**验收** 验证本人权限、评价窗口边界、修改和必填原因、到期锁定、自动评价重复执行及其与主动评价的竞争。统计分别展示主动与自动结果，参与率口径明确。根据实际设计确定最小可用的到期执行方式并记录调用方式。七个自然日的截止时刻及允许统计的具体范围若仍不明确，在实施相应部分前确认。

**交接** 截止时间口径、到期执行方式、评价来源和统计字段。

## T06 简易界面与首版流程联验

**前置** T01 至 T05 已完成所依赖的功能。

**范围** 基于已有真实 API 提供本地测试账号使用的简易界面，覆盖提交人、分派人员和处理人的日常动作，并呈现历史、撤销及评价。按角色展示允许操作，后端权限持续生效。基于实际接口串联首版流程，修复本阶段发现的范围内缺陷。

**验收** 从界面完整走通提交、分派、接单、处理、未解决退回、再次处理、确认关闭和评价。补验直接撤销、撤销申请、改派后权限变化、重复建单、终态后新会话新单，以及无评价到期自动好评。通过真实 API 验证代表性越权与并发冲突。时间边界可使用受控测试时间，记录具体方式。交付可操作的本地启动和测试账号说明，区分已完成、未完成和未验证能力。

**交接** 首版本地测试结果、已知缺陷和下一阶段待决项。正式身份接入、通知、附件、差评复核和复杂 SLA 继续按需求分期处理。
